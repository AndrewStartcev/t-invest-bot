# Правила клиента и подтверждения

Обновление 06.10.2026 учитывает текстовое ТЗ, переписку и файл «Мониторинг покупок.docx». Прежние режимы, рублёвые лимиты, доли закрытия, расписание и отдельные клиентские кабинеты сохранены. Новые переключатели изначально выключены, чтобы обновление не изменяло торговое поведение без настройки клиентом.

## Как настроить

В кабинете открой «Настройки», блок «Правила из ТЗ». Включи условные подтверждения, проверку существующей позиции и порог прибыли 0,15%. Ограничение позиции процентом собственного портфеля необязательное. По уточнению клиента оно ему не требуется: оставь выключенным. Саму функцию сохраняем. Сохрани настройки. Реальная торговля и условное автокопирование включаются своими прежними переключателями.

Процентный лимит относится к **собственному выбранному торговому счёту клиента**, а не к портфелю автора. Перед реальной покупкой запрашивается свежая стоимость портфеля брокера. Количество лотов уменьшается с учётом уже имеющейся позиции и зарезервированных ботом покупок. Если целый лот не помещается в предел, заявка пропускается. Рублёвые лимиты и доступные средства также проверяются. Для фьючерсов ограничивается ГО относительно стоимости портфеля, а не номинальная стоимость контракта. Для симуляции процентный лимит не применяется: у неё нет достоверной стоимости брокерского портфеля.

Для Telegram укажи токен выделенного бота и свой числовой ID личного чата, нажми `/start` у бота и проверь отправку. Включи «Подтверждения кнопками Telegram». Этот бот не должен одновременно обслуживаться сторонним `getUpdates` или webhook. Сервер сам принимает нажатия; публичный webhook и дополнительные открытые порты не нужны. При выключенном переключателе сохраняются обычные уведомления и решения через панель.

## Как проходит сделка

Новая операция автора проходит расчёт количества, денег, лотов и лимитов. При необходимости ручного решения в Telegram и журнале появляется рассчитанная заявка: актив, направление, количество, цена, сумма либо ГО, счёт и причина вопроса. Заблокированная лимитами сделка не превращается в разрешённую нажатием кнопки.

«Подтвердить» выполняет текущую заявку после повторной проверки. «Отклонить» завершает её без сделки. «Подтвердить и больше не спрашивать по активу» выполняет текущую заявку и разрешает последующие операции этого актива без повторных вопросов, включая режим подтверждения каждой заявки. Торговый режим при этом не включается. Разрешение действует только в данном кабинете для выбранного автора, счёта и тикера с классом инструмента. Его можно снять в журнале. Все жёсткие лимиты сохраняются.

Решение действует пять минут. Изменение счёта, токена, настроек, цены, количества, расписания либо отключение источника блокирует отправку устаревшей заявки. В журнале можно подготовить новое подтверждение с новым расчётом по исходному сигналу. Повторное нажатие не отправляет вторую заявку. После сетевого сбоя уже отправлявшаяся заявка требует сверки с брокером, автоматическая повторная отправка запрещена. Расписание не отменяет уже выставленные заявки.

Каждый клиент хранит свои токены, настройки, решения и список разрешённых активов в своём каталоге. Кнопка другого клиента не даёт доступа к его заявке. Telegram принимает торговое решение только от настроенного пользователя в его личном чате.

## Что пока нельзя подтвердить данными источника

Портфель выбранного автора (например, LinMath) читается перед обработкой покупок и продаж, когда включены условные подтверждения. Кабинет показывает имя автора, время и прочитанные строки. При покупке видимая ненулевая позиция вызывает подтверждение; отображаемые 0% исключены по требованию клиента. Это исключение относится к показанной доле, а не доказывает отсутствие фактических бумаг. Скрытый актив или ошибка загрузки требуют решения оператора.

Снимки портфеля сохраняются отдельно для каждого автора в состоянии клиентского процесса. После обнаруженной продажи оставшаяся ненулевая позиция вызывает подтверждение. В причине видна предыдущая и текущая доля, если доступны оба снимка; без предыдущего снимка остаток также требует решения. Уменьшение процентной доли не используется как доказательство количества проданных бумаг. После перезапуска сравнение продолжает использовать сохранённый снимок. Cookies банковской сессии клиенту не передаются.

Минимальная прибыль проверяется при покупке и продаже. При известной доходности значение 0,15% включительно проходит эту проверку; ниже порога требуется подтверждение. Проверка оставшейся позиции и другие причины подтверждения продолжают действовать. Отсутствующая доходность не считается нулём и требует решения оператора.

Технический выбор единиц убран из клиентского интерфейса. Ранее сохранённый формат сохраняется внутри настроек; по величине числа формат не угадывается. Фактические единицы relativeYield ещё требуют сверки с авторизованным экраном Пульса: пока они неизвестны, программа просит подтверждение с понятной причиной. Удаление поля не означает, что формат источника уже проверен.

Реальные заявки остаются лимитными: цена берётся из свежего стакана и проверяется повторно перед отправкой. Стоп-лимит и тейк-профит поддерживаются API банка, но в этом обновлении не добавляются: документ клиента содержит вопрос об их возможности, а не параметры таких заявок.

Сценарий «продажа, затем покупка для закрытия короткой позиции» добавлен в **симуляцию**, отдельным переключателем. Условная позиция отрицательная; встречная покупка закрывает её по установленным долям и лимитам закрытия. Открытие дополнительно ограничивается лимитами покупки и продажи; повторное увеличение короткой позиции запрещено. Выключение переключателя запрещает новые открытия, но позволяет закрывать уже созданную условную позицию. Симуляция не показывает фактическую короткую позицию автора.

Реальные короткие позиции не включены. Продажа остаётся ограничена собственной длинной позицией, купленной ботом. Если брокер сообщает отрицательную позицию, обычная покупка тоже блокируется, чтобы не выдать открытие за закрытие. Для полноценного реального сценария нужны проверенные данные источника и отдельная проверка маржинальных расчётов брокера.

## Обновление сервера

```bash
cd /opt/t-invest-bot
git pull --ff-only
sudo systemctl restart t-invest-bot
sudo systemctl status t-invest-bot --no-pager
```

Обнови страницу кабинета через Ctrl+F5. Дополнительная миграция клиентов или изменение nginx не нужны. После настройки сначала проверь симуляцию и кнопки Telegram; живое исполнение на VPS этим обновлением автоматически не проверяется.
