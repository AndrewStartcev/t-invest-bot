# Запуск на invest.argokov.ru

Сервер: Ubuntu 22.04/24.04 или Debian 12 с systemd и nginx. Установщик предназначен для VPS, где nginx управляется обычными файлами `/etc/nginx/sites-available`. Для сервера с ISPmanager, Apache, контейнерным nginx или другой панелью сначала адаптируй виртуальный хост, не запускай установщик вслепую. Остальные виртуальные хосты установщик не удаляет; выпуск сертификата выполняется через отдельный webroot.

Бот запускается автоматически после перезагрузки. Панель и окно Пульса доступны по HTTPS с логином/паролем. Компьютер клиента держать включённым не нужно; серверу нужен исходящий интернет к Т-Банку и Telegram. Установщик не выставляет заявки и не включает торговый режим.

## 1. Подготовить DNS

В зоне `argokov.ru` создай A-запись:

| Поле | Значение |
| --- | --- |
| Имя | `invest` |
| Тип | `A` |
| Значение | Публичный IPv4 сервера |

Если есть AAAA-запись, она должна вести на рабочий IPv6 этого же сервера; ошибочную запись убери. Для первого запуска отключи CDN-прокси у этой записи, если используешь его. На сервере и в сетевом экране провайдера должны быть доступны входящие 80/443 и SSH. Порты 8765, 6080 и 5901 наружу открывать не требуется: сервисы слушают только localhost. Не сбрасывай существующие правила firewall.

## 2. Загрузить проект

Выполняй команды по SSH. Нужны root или sudo и доступ к репозиторию.

```bash
sudo apt-get update
sudo apt-get install -y git python3
sudo git clone https://github.com/AndrewStartcev/t-invest-bot.git /opt/t-invest-bot
cd /opt/t-invest-bot
sudo bash scripts/install_server.sh invest.argokov.ru
```

Если репозиторий закрыт, используй свой настроенный доступ к GitHub; не вставляй токен GitHub в URL команды. Если папка уже существует, не клонируй поверх неё: проверь `git status`, затем обнови её. Ветка должна содержать `scripts/install_server.sh`, `scripts/enable_https.sh`, `broker_http.py`, `server_config.py` и каталог `deploy/`. Пока серверные изменения не отправлены в GitHub, клонирование старой ветки их не даст.

Установщик поставит Python-окружение и Chromium Playwright, виртуальный экран и доступ к нему, отдельный виртуальный хост nginx и пять systemd-сервисов. При первом запуске запросит пароль для пользователя **admin**. Это пароль панели, а не API-токен банка. Пароль вводится интерактивно и не помещается в историю команд.

До выпуска HTTPS домен возвращает 503; страница входа и токены по HTTP не передаются. Если установка не прошла, остановись на первой ошибке и пришли её текст без секретов.

## 3. Выпустить HTTPS

После обновления DNS выполни, заменив email своим адресом:

```bash
sudo bash /opt/t-invest-bot/scripts/enable_https.sh invest.argokov.ru you@example.com
```

Скрипт получает сертификат, проверяет новый конфиг nginx и включает автоматическое продление. Открой:

`https://invest.argokov.ru/`

Логин — **admin**, пароль — заданный при установке. Его требуют и панель, и окно серверного браузера. Для смены пароля:

```bash
sudo htpasswd -B /etc/nginx/t-invest-bot.htpasswd admin
```

Не используй `-c` при смене: этот параметр создаёт файл заново. Для проверки продления:

```bash
sudo certbot renew --dry-run
```

## 4. Подключить Пульс на сервере

1. В панели нажми **«Войти в Т-Банк»**. Окно с браузером банка автоматически откроется на устройстве клиента.
2. Если браузер заблокировал всплывающее окно, разреши его для этого сайта или нажми **«Открыть серверный браузер»**. Также доступна ссылка **«Браузер Пульса»** в верхней части панели.
3. В Chrome на этом экране войди в Т-Банк своим обычным способом. Банк может дополнительно подтвердить вход с нового устройства/IP. Вводи телефон и код непосредственно в браузере банка.
4. Панель сама вернёт браузер к сделкам профиля и подтвердит вход. Выбери ссылку нужного автора в настройках.
5. После подтверждения вкладку серверного браузера можно закрыть. Мониторинг продолжится. При завершении сессии банком повтори вход.

Пульс остаётся на `www.tbank-online.com`. Вход на ПК клиента не переносится автоматически на сервер: сервер имеет собственный профиль браузера. При восстановлении сохранённой сессии браузер работает без окна; для повторного входа кнопка в панели открывает видимое окно на серверном экране.

Окно видно и управляется у клиента через HTTPS/noVNC; сам Chromium работает на сервере. Обычный вход на сайт банка в локальном браузере клиента не передаст серверу сеанс. Для нескольких клиентов нужны отдельные экземпляры или многопользовательская изоляция, которой сейчас нет.

Chromium и Playwright создают временные файлы в `TMPDIR=/run/t-invest-bot`: этот каталог создаёт systemd с правами 0700 и удаляет при остановке сервиса. `ProtectSystem=strict` сохраняется. `/tmp/.X11-unix` остаётся видимым для подключения к Xvfb. Статические файлы noVNC отдаёт nginx с MIME-типами; только WebSocket `/desktop/websockify` проксируется через websockify.

Сервис VNC ожидает запуска Openbox, перед подключением задаёт раскладку `us` через `setxkbmap` и использует XKB для передачи клавиш. Клавиатура, мышь и буфер обмена явно разрешены (`-input KMBC`); настройки из внешнего rc-файла не загружаются. Ссылка noVNC отключает сохранённый режим «только просмотр». Если клавиши всё ещё не передаются, проверь `systemctl status t-invest-window-manager t-invest-vnc` и `journalctl -u t-invest-vnc -n 50 --no-pager`; работоспособность ввода нужно подтвердить в окне на устройстве клиента.

## 5. Подключить API-токены

Выпускай токены на `https://www.tbank.ru/invest/settings/api/`.

| Блок панели | Какой токен нужен |
| --- | --- |
| «Брокерский счёт» | Только для чтения, с доступом к нужному счёту |
| «Реальные заявки» | Отдельный токен с полным доступом к открытому брокерскому счёту |

Полный доступ в блоке чтения намеренно отклоняется. Это не ошибка токена: вставь его в торговый блок, а для чтения выпусти отдельный read-only токен. Песочница в этой панели не подключается: используемый адрес API относится к реальному контуру.

Вставь токены в соответствующие поля и выбери счета. Они сохранятся на сервере, а не на ПК клиента. Сохранённые токены интерфейс обратно не показывает. Начни с режима **«Реальная торговля → Выключена»** и проверь портфель, мониторинг и Telegram. Для теста выставления заявки используй режим подтверждения и предварительно согласованную минимальную сумму. Установка сама по себе не подтверждает возможность совершения реальной сделки.

## 6. Если токен не подключается

Сначала смотри точное сообщение рядом с полем. Серверная версия принимает API-токен с внешними кавычками или префиксом `Bearer`, убирая только эти артефакты. Пробелы внутри токена, переносы и кириллица отклоняются до отправки запроса. TLS-проверка остаётся включённой.

Запусти диагностику **на проблемном устройстве**, в том числе на сервере:

```bash
cd /opt/t-invest-bot
sudo -u t-invest-bot .venv/bin/python scripts/diagnose_broker.py
sudo -u t-invest-bot .venv/bin/python scripts/diagnose_broker.py --token
```

Вторая команда спросит токен скрытым вводом и вызовет только `GetAccounts`. Она не сохраняет токен, не показывает ID счетов и не отправляет заявки. Для проверки на Windows открой терминал в папке проекта и выполни:

```powershell
.venv\Scripts\python.exe scripts\diagnose_broker.py --token
```

| Сообщение | Что проверить |
| --- | --- |
| Код API 40003 / HTTP 401 | Токен неактивен, неверен или отозван; выпустить новый |
| HTTP 403 | Права токена, доступ к счёту; если не помогает, поддержка банка |
| «Нужен токен только для чтения» | Полный токен введён в блок чтения |
| «Нужен торговый токен…» | Для торгового блока нужны полный доступ и открытый поддерживаемый счёт |
| TLS / сертификаты | Системное время, `ca-certificates`, корпоративный прокси/антивирус |
| DNS | Настройки DNS и разрешение имени `invest-public-api.tbank.ru` |
| Таймаут / нет связи | Исходящий 443, сеть сервера, прокси, доступность API |
| «Запрос из другого источника отклонён» | Домен в `/etc/t-invest-bot/server.env` должен совпадать с адресом панели, протокол — HTTPS |

Для сертификатов на Ubuntu/Debian:

```bash
timedatectl status
sudo apt-get install --reinstall ca-certificates
sudo update-ca-certificates
```

Не отключай проверку TLS. Диагностическая команда проверяет прямое TLS-соединение; сам Python API-клиент учитывает системные настройки HTTPS-прокси. Если прокси обязателен, настроить его нужно в окружении systemd, а не только в SSH-терминале. Значения прокси с паролями не присылай.

Мне достаточно вывода диагностики и точного текста ошибки в панели. API-токены, cookie, коды входа и файлы сессии присылать не нужно. По одному факту «на моём ПК работает» причину на другом устройстве определить нельзя.

## 7. Состояние и логи

```bash
sudo systemctl status t-invest-bot --no-pager
sudo journalctl -u t-invest-bot -n 100 --no-pager
sudo systemctl status t-invest-display t-invest-window-manager t-invest-vnc t-invest-desktop --no-pager
sudo journalctl -u t-invest-desktop -n 50 --no-pager
sudo nginx -t
curl http://127.0.0.1:8765/api/health
```

`api/health` подтверждает работу HTTP-сервера; он не проверяет банк, токен или состояние Пульса.

Если серверный экран пустой, сначала нажми «Войти в Т-Банк»: при обычном мониторинге сохранённой сессии окно скрыто. Если окно не появляется, проверь display и основной сервис. Если noVNC сообщает о потере соединения, проверь desktop/vnc и websocket-проксирование nginx. При ошибке установки браузера повтори:

```bash
sudo env PLAYWRIGHT_BROWSERS_PATH=/opt/t-invest-bot/.playwright /opt/t-invest-bot/.venv/bin/python -m playwright install --with-deps chromium
sudo systemctl restart t-invest-bot
```

## 8. Обновления и данные

```bash
sudo bash /opt/t-invest-bot/scripts/update_server.sh
```

Обновление выполняется только с чистым checkout и через fast-forward. Скрипт останавливает бот, обновляет код/зависимости/браузер, выполняет тесты и запускает бот. При ошибке он остаётся выключенным: исправь причину и запусти `sudo systemctl restart t-invest-bot`. Остальные systemd/nginx-конфиги обновление автоматически не заменяет. При изменении файлов `deploy/` установи их повторно и выполни `systemctl daemon-reload`; для обычных изменений Python это не нужно.

Постоянные данные находятся в `/var/lib/t-invest-bot`: токены, выбор счетов, настройки, сессия Пульса, события и журнал реальных заявок. Их нельзя удалять при обновлении: журнал нужен для защиты от повторной отправки. Для резервного копирования останови бот и скопируй весь этот каталог в защищённое хранилище, затем запусти бот. Это резервная копия с секретами.

Конфигурация сервиса — `/etc/t-invest-bot/server.env`. Обычный запуск на Windows продолжает использовать `.local/` в папке проекта. При переносе настроек с ПК оставь реальную торговлю выключенной и повторно проверь счета и лимиты на сервере; новую сессию Пульса создай входом на сервере.

## Проверки перед выдачей

Код проверен локальными автоматическими тестами: HTTPS-origin, защита от чужого Origin, отдельный каталог данных, выбор Linux Chromium, диагностика токена/DNS/TLS/таймаута, отсутствие повторной отправки и торговые правила. Установка пакетов, запуск реального noVNC/Chromium и получение сертификата на VPS пока не выполнены: для этого нужен доступ к целевому серверу и направленный домен. Работа с реальным клиентским токеном также пока не проверялась.
