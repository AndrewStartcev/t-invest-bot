# Запуск на invest.argokov.ru

## Несколько независимых клиентов

После включения этого режима каждый логин имеет свой процесс, API-токены, выбранные счета, лимиты, Telegram, позиции, счётчики Пульса и журнал заявок. Данные не переключаются внутри общих глобальных переменных. Один банк-браузер владельца остаётся в отдельном процессе: клиенты получают только данные сделок через закрытый локальный RPC. Банковские cookies не копируются в клиентские каталоги. Разные клиенты могут выбрать разные профили Пульса, но один кабинет пока отслеживает один профиль.

Перед переносом выключи **реальную торговлю** и дождись завершения запросов панели. Существующие выставленные заявки это не отменяет; проверь их отдельно в приложении банка. Во время переноса не работайте в панели — она временно недоступна. Запусти от root:

```bash
cd /opt/t-invest-bot
git pull --ff-only
bash scripts/enable_multiuser.sh invest.argokov.ru
```

Скрипт требует уже настроенные HTTPS и общий источник. Перед изменениями запускает тесты, останавливает бот и создаёт защищённую резервную копию. Старый логин `admin` и его пароль сохраняются; токены, настройки, позиции и журнал переносятся в `/var/lib/t-invest-bot/clients/admin/`. Браузерный профиль переносится в `/var/lib/t-invest-bot/source/pulse-browser/`. Обычно сохранённый банковский сеанс восстанавливается, но при требовании банка владелец повторяет вход на `/source-admin/`. Миграция не включает торговлю.

Резервная копия `/var/lib/t-invest-migration-XXXXXXXX` содержит секреты и закрыта для всех, кроме root. Не публикуйте её. При ошибке скрипт восстанавливает прежнюю конфигурацию и данные; неудачная попытка сохраняется внутри копии как `failed-data`, а не удаляется. После успешной установки копия остаётся для восстановления. Повторное выполнение не переносит кабинеты заново.

Как подключить второго клиента:

1. Открой `https://invest.argokov.ru/source-admin/` под прежним `source-owner`.
2. В блоке «Клиентские кабинеты» создай, например, логин `client2` и отдельный начальный пароль.
3. Дай клиенту `https://invest.argokov.ru/` и его логин/пароль. Он подключает **свои** API-токены и выбирает **свои** счета. Новый кабинет пустой, реальная торговля выключена.
4. Клиент меняет пароль в «Настройки → Мой кабинет». Требуется текущий пароль. После смены нужно обновить страницу и войти с новым паролем. Пароль другого клиента не меняется. Для проверки двух кабинетов на одном ПК используй разные браузерные профили/приватные окна: браузер запоминает Basic Auth логин для сайта.

В этой версии лимит — 10 кабинетов на установку; это защитный предел, не гарантия производительности VPS. Источник общий, поэтому при его отключении новые данные не поступают всем клиентам. Уже отправленные брокерские заявки и обновление собственного портфеля работают независимо; для нескольких клиентов с разными аккаунтами суммарные ограничения API и ресурсы сервера нужно наблюдать.

Файл паролей `/var/lib/t-invest-auth/clients.htpasswd` содержит bcrypt-хеши, а не пароли. Каталог имеет права 2750, файл — 0640: сервис может менять пароли, nginx — читать для проверки входа. Пароли передаются `htpasswd` только через stdin, не через аргументы команды. Создать логин может только владелец источника, публичной регистрации нет. API-токены по-прежнему хранятся в файлах 0600 без шифрования содержимого: root/администратор ОС может их прочитать. Изоляция веб-кабинетов не является защитой от компрометации сервера.

Nginx заменяет пользовательский заголовок логина своим `$remote_user` после проверки пароля и добавляет служебный ключ из `/etc/t-invest-bot/client-proxy.conf`. Шлюз проверяет этот ключ и выбирает процесс строго по проверенному логину. Клиент не может указать другой кабинет в JSON/URL. Каждый внутренний HTTP-процесс дополнительно требует свой случайный ключ. Порты доступны только через loopback; публично остаётся nginx. `source-owner` не получает клиентские токены/портфели через страницу управления источником.

Проверка на VPS перед переносом включает реальный `htpasswd` и отдельный тестовый nginx на свободных loopback-портах: подмена заголовка логина и доступ клиента к `/source-admin/`, noVNC и WebSocket должны быть отклонены. Эти тесты не перезапускают системный nginx и не вызывают брокерские API. В окружении без nginx/apache2-utils соответствующие проверки пропускаются; это явно отражается в выводе тестов.

## Источник Пульса владельца и API клиента

Без `enable_multiuser.sh` этот прежний режим предназначен для **одного клиента на одной установке**. Банк авторизует владелец сервиса, клиент подключает собственные API-токены. Второй клиент с тем же логином/паролем увидит тот же портфель и настройки. Чтобы разделить клиентов, выполни переключение из первого раздела; не раздавай один логин разным клиентам.

После установки HTTPS обнови сервер:

```bash
cd /opt/t-invest-bot
git pull --ff-only
bash scripts/configure_shared_source.sh invest.argokov.ru
```

Скрипт попросит задать **новый отдельный пароль** для `source-owner`. Не используй пароль клиентского `admin`. Существующие API-токены и настройки сохраняются. Скрипт устанавливает актуальные units, в том числе исправление запуска Openbox, закрывает прежние подключения VNC, проверяет nginx, перезапускает сервисы и ждёт доступности приложения. При ошибке настройки env/nginx восстанавливаются; вывод ошибок нужно прочитать, а не продолжать вслепую.

1. Владелец открывает `https://invest.argokov.ru/source-admin/`, входит как `source-owner` и нажимает «Открыть окно входа». В банковском окне он проверяет, что используется его аккаунт, и сам вводит свой телефон, пароль и SMS. Если там уже открыт чужой аккаунт, сначала выйдите из него через сайт банка. Не передавайте эти данные в чат. Если браузер запрашивает пароль для `/desktop/`, укажите тот же `source-owner`.
2. После входа нажмите «Проверить сеанс» и дождитесь подключения источника. Если сеанс истёк, повторный вход выполняет владелец на этой же странице. Клиент не должен выполнять банковский вход.
3. Клиент открывает `https://invest.argokov.ru/`, входит как `admin` с отдельным паролем панели, выбирает профиль Пульса и подключает свой read-only API-токен для портфеля. Для реальных заявок нужен отдельный торговый API-токен клиента. Токены создаются самим клиентом на `https://www.tbank.ru/invest/settings/api/` и вводятся непосредственно в панель.
4. Проверьте номер счёта и портфель клиента. До проверки источника и лимитов оставьте реальную торговлю выключенной. Банковский аккаунт владельца служит источником чтения Пульса; счёт для брокерской заявки определяется клиентским торговым токеном и выбранным счётом.

Проверка разделения после установки (curl попросит пароль `admin`):

```bash
curl -u admin -s -o /dev/null -w '%{http_code}\n' https://invest.argokov.ru/desktop/vnc.html
curl -u admin -s -o /dev/null -w '%{http_code}\n' https://invest.argokov.ru/source-admin/
```

Оба запроса с клиентским логином должны вернуть **401**. Основная панель с этим логином должна открываться. Прямые клиентские POST к `/api/auth/start`, `/api/auth/check`, `/api/browser/show` возвращают 403. Владелец имеет доступ только к состоянию и командам источника через `/source-admin/api/`; этот API не возвращает клиентский портфель и настройки.

Защита обеспечивается отдельными файлами Basic Auth для панели и источника, HTTPS и служебным случайным ключом между nginx и приложением. В клиентских запросах nginx удаляет заголовок ключа; приложение дополнительно проверяет ключ на маршрутах владельца. `/desktop/` и его WebSocket защищены **паролем владельца**, а не клиента. Ключ хранится в `server.env` и `source-proxy.conf` с правами 0600. Не публикуйте вывод `nginx -T`, содержимое env или браузерного профиля: там есть служебные секреты. Повторный выпуск HTTPS через штатный скрипт сохраняет разделение доступа.

**Граница защиты:** HTTPS защищает передачу данных. Банковские cookies владельца и API-токены клиента хранятся на VPS; API-токены — в файлах с правами 0600, без шифрования содержимого. Администратор ОС/root может прочитать эти файлы. Не обещайте клиенту, что токены остаются исключительно на его устройстве. Клиент не получает пароль источника или SSH/root-доступ. Эта версия не добавляет 2FA в панель и не устраняет компрометацию сервера.

В локальном режиме Windows по умолчанию остаётся прежний личный вход. Серверный общий источник включается через `TINVEST_PULSE_SOURCE=shared` и требует HTTPS origin и служебный ключ; неверная конфигурация не запускается.


Сервер: Ubuntu 22.04/24.04 или Debian 12 с systemd и nginx. Установщик предназначен для VPS, где nginx управляется обычными файлами `/etc/nginx/sites-available`. Для сервера с ISPmanager, Apache, контейнерным nginx или другой панелью сначала адаптируй виртуальный хост, не запускай установщик вслепую. Остальные виртуальные хосты установщик не удаляет; выпуск сертификата выполняется через отдельный webroot.

Бот запускается автоматически после перезагрузки. Панель и окно Пульса доступны по HTTPS с логином/паролем. Компьютер клиента держать включённым не нужно; серверу нужен исходящий интернет к Т-Банку и Telegram. Установщик не выставляет заявки и не включает торговый режим.

## 1. Подготовить DNS

В зоне `argokov.ru` создай A-запись:

| Поле | Значение |
| --- | --- |
| Имя | `invest` |
| Тип | `A` |
| Значение | Публичный IPv4 сервера |

Если есть AAAA-запись, она должна вести на рабочий IPv6 этого же сервера; ошибочную запись убери. Для первого запуска отключи CDN-прокси у этой записи, если используешь его. На сервере и в сетевом экране провайдера должны быть доступны входящие 80/443 и SSH. Порты 8765, 6080 и 5901 наружу открывать не требуется: сервисы слушают только localhost. Не сбрасывай существующие правила firewall.

## 2. Загрузить проект

Выполняй команды по SSH. Нужны root или sudo и доступ к репозиторию.

```bash
sudo apt-get update
sudo apt-get install -y git python3
sudo git clone https://github.com/AndrewStartcev/t-invest-bot.git /opt/t-invest-bot
cd /opt/t-invest-bot
sudo bash scripts/install_server.sh invest.argokov.ru
```

Если репозиторий закрыт, используй свой настроенный доступ к GitHub; не вставляй токен GitHub в URL команды. Если папка уже существует, не клонируй поверх неё: проверь `git status`, затем обнови её. Ветка должна содержать `scripts/install_server.sh`, `scripts/enable_https.sh`, `broker_http.py`, `server_config.py` и каталог `deploy/`. Пока серверные изменения не отправлены в GitHub, клонирование старой ветки их не даст.

Установщик поставит Python-окружение и Chromium Playwright, виртуальный экран и доступ к нему, отдельный виртуальный хост nginx и пять systemd-сервисов. При первом запуске запросит пароль для пользователя **admin**. Это пароль панели, а не API-токен банка. Пароль вводится интерактивно и не помещается в историю команд.

До выпуска HTTPS домен возвращает 503; страница входа и токены по HTTP не передаются. Если установка не прошла, остановись на первой ошибке и пришли её текст без секретов.

## 3. Выпустить HTTPS

После обновления DNS выполни, заменив email своим адресом:

```bash
sudo bash /opt/t-invest-bot/scripts/enable_https.sh invest.argokov.ru you@example.com
```

Скрипт получает сертификат, проверяет новый конфиг nginx и включает автоматическое продление. Открой:

`https://invest.argokov.ru/`

Логин панели — **admin**, пароль — заданный при установке. В режиме общего источника банковское окно требует отдельный `source-owner`; в личном режиме используется `admin`. Для смены пароля:

```bash
sudo htpasswd -B /etc/nginx/t-invest-bot.htpasswd admin
```

Не используй `-c` при смене: этот параметр создаёт файл заново. Для проверки продления:

```bash
sudo certbot renew --dry-run
```

## 4. Подключить Пульс на сервере

**Для общего источника используй `/source-admin/` и порядок из первого раздела.** Шаги ниже относятся только к прежнему личному режиму без `TINVEST_PULSE_SOURCE=shared`.

1. В панели нажми **«Войти в Т-Банк»**. Окно с браузером банка автоматически откроется на устройстве клиента.
2. Если браузер заблокировал всплывающее окно, разреши его для этого сайта или нажми **«Открыть серверный браузер»**. Также доступна ссылка **«Браузер Пульса»** в верхней части панели.
3. В Chrome на этом экране войди в Т-Банк своим обычным способом. Банк может дополнительно подтвердить вход с нового устройства/IP. Вводи телефон и код непосредственно в браузере банка.
4. Панель сама вернёт браузер к сделкам профиля и подтвердит вход. Выбери ссылку нужного автора в настройках.
5. После подтверждения вкладку серверного браузера можно закрыть. Мониторинг продолжится. При завершении сессии банком повтори вход.

Пульс остаётся на `www.tbank-online.com`. Вход на ПК клиента не переносится автоматически на сервер: сервер имеет собственный профиль браузера. При восстановлении сохранённой сессии браузер работает без окна; для повторного входа кнопка в панели открывает видимое окно на серверном экране.

Окно видно и управляется у клиента через HTTPS/noVNC; сам Chromium работает на сервере. Обычный вход на сайт банка в локальном браузере клиента не передаст серверу сеанс. Для нескольких клиентов нужны отдельные экземпляры или многопользовательская изоляция, которой сейчас нет.

Chromium и Playwright создают временные файлы в `TMPDIR=/run/t-invest-bot`: этот каталог создаёт systemd с правами 0700 и удаляет при остановке сервиса. `ProtectSystem=strict` сохраняется. `/tmp/.X11-unix` остаётся видимым для подключения к Xvfb. Статические файлы noVNC отдаёт nginx с MIME-типами; только WebSocket `/desktop/websockify` проксируется через websockify.

Сервис VNC ожидает запуска Openbox, перед подключением задаёт раскладку `us` через `setxkbmap` и использует XKB для передачи клавиш. Клавиатура, мышь и буфер обмена явно разрешены (`-input KMBC`); настройки из внешнего rc-файла не загружаются. Ссылка noVNC отключает сохранённый режим «только просмотр». Если клавиши всё ещё не передаются, проверь `systemctl status t-invest-window-manager t-invest-vnc` и `journalctl -u t-invest-vnc -n 50 --no-pager`; работоспособность ввода нужно подтвердить в окне на устройстве клиента.

## 5. Подключить API-токены

Выпускай токены на `https://www.tbank.ru/invest/settings/api/`.

| Блок панели | Какой токен нужен |
| --- | --- |
| «Брокерский счёт» | Только для чтения, с доступом к нужному счёту |
| «Реальные заявки» | Отдельный токен с полным доступом к открытому брокерскому счёту |

Полный доступ в блоке чтения намеренно отклоняется. Это не ошибка токена: вставь его в торговый блок, а для чтения выпусти отдельный read-only токен. Песочница в этой панели не подключается: используемый адрес API относится к реальному контуру.

Вставь токены в соответствующие поля и выбери счета. Они сохранятся на сервере, а не на ПК клиента. Сохранённые токены интерфейс обратно не показывает. Начни с режима **«Реальная торговля → Выключена»** и проверь портфель, мониторинг и Telegram. Для теста выставления заявки используй режим подтверждения и предварительно согласованную минимальную сумму. Установка сама по себе не подтверждает возможность совершения реальной сделки.

## 6. Если токен не подключается

Сначала смотри точное сообщение рядом с полем. Серверная версия принимает API-токен с внешними кавычками или префиксом `Bearer`, убирая только эти артефакты. Пробелы внутри токена, переносы и кириллица отклоняются до отправки запроса. TLS-проверка остаётся включённой.

Запусти диагностику **на проблемном устройстве**, в том числе на сервере:

```bash
cd /opt/t-invest-bot
sudo -u t-invest-bot .venv/bin/python scripts/diagnose_broker.py
sudo -u t-invest-bot .venv/bin/python scripts/diagnose_broker.py --token
```

Вторая команда спросит токен скрытым вводом и вызовет только `GetAccounts`. Она не сохраняет токен, не показывает ID счетов и не отправляет заявки. Для проверки на Windows открой терминал в папке проекта и выполни:

```powershell
.venv\Scripts\python.exe scripts\diagnose_broker.py --token
```

| Сообщение | Что проверить |
| --- | --- |
| Код API 40003 / HTTP 401 | Токен неактивен, неверен или отозван; выпустить новый |
| HTTP 403 | Права токена, доступ к счёту; если не помогает, поддержка банка |
| «Нужен токен только для чтения» | Полный токен введён в блок чтения |
| «Нужен торговый токен…» | Для торгового блока нужны полный доступ и открытый поддерживаемый счёт |
| TLS / сертификаты | Сертификаты НУЦ для API `.ru`: `scripts/install_broker_ca.sh`; также время сервера и HTTPS-прокси |
| DNS | Настройки DNS и разрешение имени `invest-public-api.tbank.ru` |
| Таймаут / нет связи | Исходящий 443, сеть сервера, прокси, доступность API |
| «Запрос из другого источника отклонён» | Домен в `/etc/t-invest-bot/server.env` должен совпадать с адресом панели, протокол — HTTPS |

Для T-Invest `.ru` требуются сертификаты НУЦ Минцифры: стандартный `ca-certificates` сам по себе их не добавляет. Исправить установленный сервер:

```bash
cd /opt/t-invest-bot
git pull --ff-only
bash scripts/install_broker_ca.sh
```

Скрипт проверяет SHA-256 отпечатки, сроки и цепочку двух сертификатов из `deploy/certs/`, создаёт публичный CA bundle `/etc/ssl/t-invest-bot/broker-ca.pem`, добавляет `TINVEST_BROKER_CA_FILE` в env и перезапускает работающий бот. Доверие добавляется **только в контекст HTTP-клиента T-Invest**, поверх стандартных CA: сертификаты ОС, nginx, Playwright и Telegram не меняются. Проверка имени хоста и цепочки остаётся включённой. Затем выполняется прямой TLS-тест без токена. Установщик сервера теперь выполняет эту настройку автоматически.

Проверка сертификатов без изменения системы: `bash scripts/install_broker_ca.sh --check-only`. Повторная диагностика с тем же bundle:

```bash
sudo -u t-invest-bot env TINVEST_BROKER_CA_FILE=/etc/ssl/t-invest-bot/broker-ca.pem \
  /opt/t-invest-bot/.venv/bin/python /opt/t-invest-bot/scripts/diagnose_broker.py
```

Если ошибка сохраняется, пришли вывод этой команды и `timedatectl status`. Если настроен обязательный прокси, прямое TLS-соединение может не проходить: тест с `--token` отдельно использует HTTP-клиент и настройки прокси. Код ошибки сертификата теперь указан в сообщении панели, без отражения секретов.

Сертификаты имеют конечный срок и обновляются отдельно от токенов. Источники и отпечатки указаны в `deploy/certs/README.md`; при ротации нужно обновить сертификаты и ожидаемые отпечатки, а не отключать проверку. Let’s Encrypt сертификат поддомена этой ошибкой не затронут.

Не отключай проверку TLS. Диагностическая команда проверяет прямое TLS-соединение; сам Python API-клиент учитывает системные настройки HTTPS-прокси. Если прокси обязателен, настроить его нужно в окружении systemd, а не только в SSH-терминале. Значения прокси с паролями не присылай.

Мне достаточно вывода диагностики и точного текста ошибки в панели. API-токены, cookie, коды входа и файлы сессии присылать не нужно. По одному факту «на моём ПК работает» причину на другом устройстве определить нельзя.

`api/health` подтверждает работу HTTP-сервера; он не проверяет банк, токен или состояние Пульса.

Если серверный экран пустой, сначала нажми «Войти в Т-Банк»: при обычном мониторинге сохранённой сессии окно скрыто. Если окно не появляется, проверь display и основной сервис. Если noVNC сообщает о потере соединения, проверь desktop/vnc и websocket-проксирование nginx. При ошибке установки браузера повтори:

```bash
sudo env PLAYWRIGHT_BROWSERS_PATH=/opt/t-invest-bot/.playwright /opt/t-invest-bot/.venv/bin/python -m playwright install --with-deps chromium
sudo systemctl restart t-invest-bot
```

## 8. Обновления и данные

```bash
sudo bash /opt/t-invest-bot/scripts/update_server.sh
```

Обновление выполняется только с чистым checkout и через fast-forward. Скрипт останавливает бот, обновляет код/зависимости/браузер, выполняет тесты и запускает бот. При ошибке он остаётся выключенным: исправь причину и запусти `sudo systemctl restart t-invest-bot`. Остальные systemd/nginx-конфиги обновление автоматически не заменяет. При изменении файлов `deploy/` установи их повторно и выполни `systemctl daemon-reload`; для обычных изменений Python это не нужно.

Постоянные данные находятся в `/var/lib/t-invest-bot`: токены, выбор счетов, настройки, сессия Пульса, события и журнал реальных заявок. Их нельзя удалять при обновлении: журнал нужен для защиты от повторной отправки. Для резервного копирования останови бот и скопируй весь этот каталог в защищённое хранилище, затем запусти бот. Это резервная копия с секретами.

Конфигурация сервиса — `/etc/t-invest-bot/server.env`. Обычный запуск на Windows продолжает использовать `.local/` в папке проекта. При переносе настроек с ПК оставь реальную торговлю выключенной и повторно проверь счета и лимиты на сервере; новую сессию Пульса создай входом на сервере.

## Проверки перед выдачей

Код проверен локальными автоматическими тестами: HTTPS-origin, защита от чужого Origin, отдельный каталог данных, выбор Linux Chromium, диагностика токена/DNS/TLS/таймаута, отсутствие повторной отправки и торговые правила. По присланным владельцем журналам сервисы установлены на VPS, форма банка открывалась; сообщалось об отсутствии ввода. Исправлен недопустимый аргумент Openbox. Живые проверки клавиатуры и нового разделения доступа выполняются владельцем на сервере; напрямую подключиться к VPS из текущего окружения не удалось. Работа с реальным клиентским токеном также пока не проверялась.

# Расписание мониторинга

В настройках каждого кабинета есть переключатель «Работать по расписанию», дни недели и время начала/окончания по Москве (UTC+3). Без расписания сохраняется прежний круглосуточный режим. Сервер работает независимо от открытого браузера клиента.

Начало входит в интервал, окончание — нет. Ночной интервал относится к выбранному дню начала: пятница 22:00–02:00 заканчивается в субботу в 02:00. Вне расписания автоматические запросы сделок Пульса, уведомления и автокопирование приостановлены. При возобновлении первая проверка устанавливает новую точку отсчёта: накопленные за перерыв сделки автоматически не повторяются. Опрос выполняется с заданным интервалом; уже начатый сетевой запрос может завершиться после окончания окна.

Обновление собственного портфеля и сверка уже выставленных заявок продолжаются. Расписание не отменяет заявки у брокера и не блокирует явные ручные действия клиента.

## Поддержание сеанса Пульса и быстрый вход

Отдельный таймер каждые 600 секунд выводит страницу Пульса на передний план, прокручивает её и заново открывает страницу, чтобы выполнилась штатная логика авторизации сайта. Он работает вне расписания и при выключенном мониторинге; не вызывает сканирование сделок или отправку заявок. Занятый сетевым запросом браузер выполнит обслуживание после завершения запроса. Продление банковской сессии этим способом пока требует проверки на реальном сервере.

Для настройки быстрого кода владельца:

```bash
cd /opt/t-invest-bot
git pull --ff-only
sudo python3 scripts/configure_pulse_login.py
sudo systemctl restart t-invest-bot
```

Скрипт дважды запросит код со скрытым вводом и сохранит `PULSE_QUICK_PIN` в `/etc/t-invest-bot/server.env` с правами 0600. Код не попадает в Git, HTTP-ответы или настройки клиентов; шлюз удаляет эту переменную из окружения клиентских процессов. Первый вход и запрос SMS выполняет владелец через `/source-admin/`.

Автоввод разрешён только на HTTPS-страницах разрешённых доменов банка с текстом «код быстрого доступа» и единственным видимым полем на четыре цифры. Формы SMS, обычного пароля, неизвестные формы и сообщение о неверном коде не заполняются. После одной попытки устанавливается локальная блокировка повторного ввода, сохраняющаяся после перезапуска. Она снимается после успешного чтения авторизованных данных либо явной повторной настройки кода этим скриптом. Если банк изменит форму быстрого входа, она потребует отдельной адаптации по её реальному экрану.

Ошибки загрузки больше не прекращают восстановление сохранённого браузерного профиля навсегда. Восстановление страницы допускает быстрый вход, но успешный вход подтверждается только фактическим доступом к данным. Постоянная банковская авторизация без SMS не гарантируется. На реальном сервере нужно проверить работу хотя бы две ночи без ручного открытия окна.

Первичная проверка входа общего источника читает только доступный список инструментов с пустыми счётчиками, без загрузки истории, проверки портфеля или клиентских правил. Она не зависит от расписания торговли. Запросы к внутреннему API Пульса прерываются через 10 секунд; чтение списка и накопленной истории имеет общий бюджет 40 секунд, проверяемый между запросами. Последний начатый запрос может добавить до 10 секунд. Ошибка не подтверждает авторизацию; запрос повторяется автоматически. В кабинетах ожидание отображается спиннером, подробная диагностика остаётся у владельца.

Рабочий домен браузера Пульса — `www.tbank.ru`. Сохранённые ссылки `tbank-online.com` нормализуются в `.ru` без ручного изменения клиентских настроек. Ранее выданные разрешения для активов сохраняются для того же автора, счёта и инструмента. При смене домена банк может потребовать вход на `.ru`. В `/source-admin/` показаны отдельно сообщение авторизации и сообщение чтения данных: подтверждение входа не скрывает ошибку чтения общего источника.
