# Архитектура и реализация

## Поток данных

```text
Пульс → адаптер источника → нормализованная операция → дедупликация
      → правила и контроль риска → подтверждение в админке (если нужно)
      → T-Invest API → журнал статусов заявки
```

Адаптер Пульса читает внутренние запросы сайта в авторизованном браузере. Это не документированный публичный API. Формат и доступность могут измениться, поэтому адаптер изолирован от торговой логики. Обход авторизации и ограничений сайта в проект не закладывается.

## Нормализованное событие

Минимум: `source`, `profile_id`, `instrument_ref`, `side`, `event_time`, `observed_at`. Опционально: цена, объём, валюта, ссылка на запись, исходная метка времени. Проверенный ответ Пульса не содержит `event_id` и объёма. Прототип использует `totalOperationsCount` по инструменту и порядок истории для локального `sequence`; стабильность этой схемы ещё нужно проверить на реальных обновлениях. Даже одинаковые время/цена/направление могут относиться к двум разным операциям.

## Состояние и доставка

- Первый снимок профиля создаёт baseline без сигналов.
- Текущий прототип хранит watermark `(profile_id, ticker, classCode, totalOperationsCount)`; прирост счётчика требует загрузить соответствующее число операций из истории. Коррекция/снижение счётчика и неполная история блокируют сигнал до разбора.
- В рабочей версии нужна транзакционная БД (предпочтительно SQLite на одном узле) со статусами `observed → eligible/blocked → pending/approved/rejected → submitted → filled/cancelled/failed`.
- Отправка заявки имеет уникальный ключ идемпотентности на счёт и исходную операцию. Намерение сохраняется в `.local/real-orders.json` до HTTP-запроса; после неопределённого ответа повторная отправка блокируется. Статус сверяется по ключу через `GetOrderState`.
- История показывает время до минуты и цену, но не ID/объём. Поэтому дедупликация по времени и цене недопустима; нужна проверка счётчика и порядка операций на нескольких обновлениях.

## Риск и безопасность

Конфигурация содержит бюджет покупки, максимальную цену лота, рублёвый лимит позиции и лимит обеспечения фьючерса. Отдельный раздел `rules.sales` задаёт режим, долю и жёсткие ограничения суммы/лота/контрактов для каждого класса. `sale_quantity()` используется и симуляцией, и реальной торговлей; дробные лоты округляются вниз. Для рублёвых продаж брокер даёт стоимость через `GetOrderPrice`: берутся стоимость без комиссий и НКД облигации. Для фьючерса используется ГО длинной позиции. Старый `sell_percent` мигрирует в проценты каждого класса. Дневной лимит и перечень разрешённых инструментов пока не реализованы. Неопределённость блокирует новую заявку; причина сохраняется. Токен для чтения отделён от токена реальной торговли, а реальная заявка привязана к выбранному счёту. Пауза уведомлений не останавливает торговлю: для этого режим переводится в «Выключена».

Для T-Invest API официально предусмотрены read-only, full-access и sandbox токены; песочница не изменяет реальный портфель ([документация токенов](https://developer.tbank.ru/invest/intro/intro/token)). Для счёта и портфеля предусмотрены `GetAccounts`, `GetPortfolio`, `GetPositions` ([счета](https://developer.tbank.ru/invest/api/users-service-get-accounts), [операции](https://developer.tbank.ru/invest/api/operations-service)). Лимиты API динамические; их надо учитывать отдельно от неизвестных ограничений Пульса ([лимиты](https://developer.tbank.ru/invest/intro/intro/limits)).

Админка управляет конфигурацией и читает журнал; watcher выполняется отдельно. Секрет Telegram хранится вне репозитория и не возвращается в HTTP-ответах админки. Для первой локальной демонстрации токен берётся из переменной окружения, админка слушает только `127.0.0.1`. Для удалённого доступа потребуется отдельная авторизация и HTTPS.

Уведомления вынесены в отдельный шлюз: сначала проверяется заполненный `chat_id`, затем токен, затем выполняется `sendMessage`. Если `chat_id` отсутствует, выполнение заканчивается до сетевого вызова. Настроенный получатель не расширяется автоматически до группы или канала.

## Текущий код

`pulse_replay.py` проверяет алгоритм на локальных JSON. `pulse_live.py` открывает отдельный браузер с локальным профилем, читает список инструментов и историю. `demo_admin.py` опрашивает Пульс, хранит счётчики и журнал, управляет режимами. `demo_engine.py` считает условный портфель отдельно в `.local/demo-positions.json`. `broker_read.py` допускает только чтение реального счёта. `broker_trade.py` использует отдельный токен с полным доступом: проверяет инструмент, цену, деньги, позиции, брокерские лимиты и ГО, затем отправляет лимитную заявку. Подтверждение в панели заново проверяет цену и количество. Фоновая сверка получает статус исполнения. Telegram отправляет сообщения только на указанный числовой ID.

Внутренний ответ Пульса не содержит размера лота и гарантийного обеспечения. Поэтому при живом сигнале акция рассчитывается с явно отмеченным условным лотом `1`, а фьючерс без обеспечения блокируется. Ручные демо-сценарии передают вымышленные лот и обеспечение, чтобы проверить правила без доступа к счёту. Демо-расчёт нельзя использовать для выставления реальной заявки.

Обнаружение новой публикации во время работы ещё требует живой проверки. Брокерская интеграция проверена тестами с подставными ответами, без реального токена и заявки. Нет транзакционной БД, нескольких профилей и кнопок подтверждения в Telegram. Счётчик Пульса сохраняется до обработки сигналов: аварийное завершение между этими действиями может оставить сигнал без исполнения; для надёжной эксплуатации нужен транзакционный журнал входящих событий. Выключение режима не отменяет уже выставленные лимитные заявки.

## Мониторинг собственного портфеля

Отдельный поток `broker_monitor_loop` обновляет собственный счёт каждые 30 секунд, независимо от Пульса. `GetPositions` даёт доступные/заблокированные единицы; позиции соединяются по UID с `GetPortfolio`, запрошенным в RUB. Для рублёвых бумаг стоимость равна `(currentPrice + currentNkd) × quantity`, доля — `value / totalAmountPortfolio × 100`. Для валютных инструментов без курса и фьючерсов без корректной оценки доля остаётся `null`. Это отображение, не процентный торговый лимит. Последний успешный снимок сохраняется при ошибке с отметкой времени; ответ старого счёта отбрасывается после переключения.

Состав портфеля автора Пульса не запрашивается. Поле сделки `relativeYield` сохраняется как исходное значение, но единицы и порог 0,15% не интерпретируются без сверки с экраном. Оно не даёт размер проданной позиции. Условия подтверждения при наличии позиции / пороге пока отсутствуют; ручной режим требует подтверждения каждой заявки.

## Серверная версия

`broker_http.py` объединяет HTTPS-транспорт чтения и торговли без автоматических повторов. Он нормализует внешние артефакты копирования токена, проверяет допустимые символы, показывает числовой код отказа API и различает DNS/TLS/таймауты. Текст ответа банка не выводится целиком, чтобы не отражать секреты. Типы `BrokerError` и `TradeError` на границах модулей сохранены.

Бот продолжает слушать 127.0.0.1:8765. Nginx защищает и панель, и noVNC паролем; HTTP до выпуска сертификата отдаёт 503, после — перенаправляет на HTTPS. `TINVEST_PUBLIC_ORIGIN` задаёт единственный допустимый HTTPS-origin для POST; произвольные forwarded-заголовки его не изменяют. `/api/health` проверяет только HTTP-процесс.

Chromium запускается от отдельного пользователя. Xvfb предоставляет экран :99; openbox управляет окнами, x11vnc слушает localhost:5901, websockify/noVNC — localhost:6080. После входа сохранённая сессия может восстанавливаться в headless-режиме. Ссылка «Браузер Пульса» показывает экран для ручного входа, без копирования cookie с ПК. Данные определяются `TINVEST_DATA_DIR`, на сервере — /var/lib/t-invest-bot; код — /opt/t-invest-bot. Установщик и инструкции находятся в scripts/, deploy/ и docs/SERVER.md.
