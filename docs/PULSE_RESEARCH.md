## Подтверждённые запросы

Оба наблюдались как `GET`, ответ `200`, JSON. Ниже только пути и публичные поля. **Полный URL не сохраняется:** в query есть `sessionId`, который относится к авторизованному сеансу.

| Назначение | Путь |
| --- | --- |
| Список инструментов | `/mybank/api/social-api-gateway/social/v1/profile/{profile_uuid}/instrument` |
| История инструмента | `/mybank/api/social-api-gateway/social/v1/profile/{profile_uuid}/operation/instrument/{ticker}/{classCode}` |

Список возвращает `payload.items[]` с `type`, `ticker`, `classCode`, `showName`, `currency` и `statistics.totalOperationsCount`, `statistics.maxTradeDateTime`. Есть `nextCursor` и `hasNext`. В ответе LinMath получено 29 инструментов на первой странице и `hasNext: true`.

История возвращает `payload.items[]` с `tradeDateTime`, `action` (`buy`/`sell`), `currency`, `averagePrice`; у некоторых продаж есть `relativeYield`. В первой странице по `BSPB/TQBR` было 20 операций, `hasNext: true`, `nextCursor`. **Отдельных ID операции и объёма в этом ответе нет.** Время в JSON содержит смещение `+03:00`; интерфейс браузера показал то же событие как 15:33 при 10:33 в JSON, то есть в локальном времени пользователя `+08:00`.

В примере `BSPB` список показал `totalOperationsCount: 682`, `maxTradeDateTime: 2026-10-03T10:33:00+03:00`. История содержала девять операций за 3 октября. Это подтверждает, что сравнение только последнего времени пропустит несколько сделок между опросами; нужен счётчик и загрузка всей новой части истории.

## Что требуется выяснить

| Вопрос | Состояние |
| --- | --- |
| Нужен ли вход для вкладки «Сделки» | В проверенном браузере без входа не видна, с входом доступна |
| URL и метод запроса списка инструментов | GET, путь указан выше |
| URL и метод запроса истории инструмента | GET, путь указан выше |
| Формат BUY/SELL, ID, время и цена | `buy`/`sell`, время до минуты, средняя цена; ID и объёма нет |
| Пагинация | В обоих ответах есть `nextCursor` и `hasNext`; поведение последующих страниц ещё проверить |
| Задержка публикации и лимиты | Не измерены |

Нельзя считать посты автора подтверждением сделки: упоминание тикера в тексте не означает покупку или продажу. Наблюдаемые URL — **внутренние интерфейсы сайта**, не официальный T-Invest API. Их доступность, условия использования и стабильность для отдельного сервиса пока не подтверждены. Авторизованный `sessionId` не следует переносить в код или репозиторий.

## Следующая проверка

1. Сверить `totalOperationsCount` и историю на нескольких инструментах; убедиться, что счётчик монотонен и курсор даёт все страницы.
2. Проверить повторное чтение, несколько операций с одинаковыми временем/ценой и изменение уже опубликованной истории. Возможная стратегия — запоминать счётчик по инструменту и забирать ровно его прирост, но пока это гипотеза.
3. Измерить задержку между совершением и появлением операции, частоту обновления списка и реакцию сайта на регулярные запросы. Предложенные 3–5 секунд не подтверждены.
4. Решить, как сервис будет получать данные без ручной передачи авторизованной сессии. До этого не считать live watcher готовым.

## Как снять безопасный образец в своём браузере, если потребуется повторная проверка

1. Войдите на `tbank.ru` в своём браузере и откройте профиль, где видна вкладка **«Сделки»**. Скопируйте ссылку на профиль.
2. Нажмите `F12` → **Network / Сеть** → фильтр **Fetch/XHR**. Включите **Preserve log / Сохранять журнал** и очистите список запросов.
3. Откройте вкладку «Сделки». Найдите запрос, после которого появился список инструментов; затем нажмите на один инструмент и найдите запрос, после которого появилась история BUY/SELL.
4. Для каждого из двух запросов запишите: путь URL **без query-параметров с персональными данными**, метод, HTTP-статус, основные имена полей JSON и по одному **обезличенному** примеру элемента списка/операции. Можно сделать снимок экрана вкладки Preview/Response после закрытия личных данных.
5. Удалите из примеров `Authorization`, `Cookie`, `Set-Cookie`, `x-request-id`, токены, номера счёта, телефон, email, идентификаторы сессии и любые персональные данные. **Не используйте “Copy as cURL” и не отправляйте полный HAR** — они обычно содержат действующие cookie.
6. Пришлите ссылку на профиль, два очищенных JSON-фрагмента и укажите, видна ли вкладка без входа в другом окне браузера. Если не уверены, что данные очищены, пришлите только скриншот с замазанными значениями и названиями полей.

После этого можно дополнить проверку схемы, измерить задержку и выбрать разумный интервал опроса.
