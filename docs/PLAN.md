# План работ

## 1. Источник сделок Пульса — в работе

Страница и два JSON-запроса проверены после входа пользователя: список инструментов содержит счётчик и время последней сделки, история содержит BUY/SELL, время и цену. ID и объёма операции нет. Результат записан в `PULSE_RESEARCH.md`. Осталось проверить пагинацию, стабильность счётчика, задержку публикации, сценарий нескольких сделок подряд, допустимую частоту обращения и способ получения данных без переноса авторизованной сессии. Офлайн-прототип на вымышленных данных уже использует прирост счётчика и различает одинаковые по времени/цене операции.

**Выход:** подтверждённый источник и тестовые обезличенные fixtures. Если данные доступны только через личный кабинет или нестабильны, пересмотреть способ мониторинга до торговой интеграции.

## 2. Watcher

Реальный адаптер, расписание с ограничением частоты и backoff, нормализация, долговременное состояние, контроль пропусков и повторов, журнал и метрики задержки. Проверка на двух профилях и нескольких инструментах.

## 3. Правила и T-Invest API без торговли

Токен только для чтения либо песочницы, выбор счёта, сопоставление инструментов, позиции, доступные средства, лоты и цены. Формирование проекта заявки и причин блокировки. Параметры для каждого класса активов согласовать с владельцем.

## 4. Telegram и симуляция

Уведомления, подтверждение/отклонение/тайм-аут, журнал решений, симуляция полного пути без реальных заявок. Затем испытание в песочнице, где доступно.

## 5. Реальная торговля

Только после отдельной приёмки предыдущих этапов: ограниченный пилот, минимальные лимиты, ручное подтверждение, сверка статуса заявки, аварийная пауза и наблюдение за ошибками. Переход к автоматическому исполнению — отдельное решение.

## Сейчас нужно от пользователя

Доступ к вкладке «Сделки» уже предоставлен через авторизованный браузер пользователя. Токен T-Invest API на этапе 1 не нужен. Не присылайте токен, cookie или полный HAR в чат и не кладите их в Git.
