# T-Invest Bot

Проект для наблюдения за опубликованными сделками выбранных авторов в Пульсе и последующего исполнения собственных правил через T-Invest API. На 3 октября 2026 года репозиторий начинался пустым. Сейчас есть документация, офлайн-прототип обработки снимков сделок и локальная демо-админка. Автоматического подключения к Пульсу и брокерскому счёту ещё нет; реальные заявки код не выставляет.

## Текущий прототип

`pulse_replay.py` проверяет обработку снимков сделок без доступа к аккаунту. Первый счётчик по каждой бумаге становится исходной точкой. Если счётчик вырос, прототип берёт соответствующее число новых записей из начала истории; уменьшение счётчика или неполная история вызывают ошибку. Состояние сохраняется локально, поэтому повторная подача снимка не создаёт повторных событий.

```powershell
python pulse_replay.py --state .local/pulse-count-state.json fixtures/pulse-first.json
python pulse_replay.py --state .local/pulse-count-state.json fixtures/pulse-next.json
python pulse_replay.py --state .local/pulse-count-state.json fixtures/pulse-next.json
```

Ожидается: первый запуск — 0 новых событий; второй — 2 (две одинаковые по времени и цене операции); третий — 0. `fixtures/` содержат вымышленные данные в форме наблюдаемых полей Пульса. Это офлайн-прототип: стабильность счётчика, полнота истории и работа с авторизованным источником ещё не подтверждены.

## Локальная демо-админка

```powershell
python demo_admin.py
```

Откройте `http://127.0.0.1:8765/`. Панель сохраняет профиль, интервал, ID получателя и паузу, показывает вымышленные сигналы и журнал. Она не запускает реальный мониторинг и не торгует. Telegram-токен берётся только из переменной окружения `TELEGRAM_BOT_TOKEN`; если ID получателя не указан, `telegram_notify.py` не делает сетевого запроса. Подробности — в [сценарии демо](docs/DEMO.md).
