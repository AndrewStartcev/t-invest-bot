# Расширение Яндекс Браузера / Brave: источник сделок Пульса

**Новая архитектура:** каждый клиент входит в Т-Банк в своём Яндекс Браузере (или Brave), расширение
читает открытые страницы Пульса через его авторизованную веб-сессию, а сервер
принимает только данные об инструментах, опубликованных сделках, видимых
позициях портфеля автора и статусах авторизации. **Серверный Playwright больше не запускается.**

## Как работают данные

- Админка выбирает единственного отслеживаемого автора.
- Расширение с уникальным ключом кабинета загружает список инструментов
  выбранного автора (включая статистику и последнее время сделки).
- При первом полноценном чтении создаётся **исходный снимок счётчиков**.
  Затем расширение последовательно восстанавливает историю опубликованных
  сделок **за последние 24 часа** по инструментам с подходящими датами.
  Найденные сделки появляются в админке по мере загрузки, с индикатором
  прогресса. Эта история предназначена только для просмотра: не отправляется
  в Telegram и не вызывает покупок или продаж.
- При увеличении счётчиков расширение загружает новые операции, передаёт их
  серверу, который проверяет полноту прироста, сохраняет позиции счётчиков,
  показывает новые сделки в админке и при включённых уведомлениях отправляет
  информацию в Telegram. **Брокерские заявки не отправляются.**
- Сервер хранит по каждому клиенту собственный ключ, счётчики и события.
  Смена автора начинает новый снимок и не смешивает события.
- Проверка авторизации происходит через авторизованные запросы API Пульса
  в браузере, включая периодическую проверку профиля. При явной потере входа
  отправляется однократное уведомление. Если расширение пропадает более
  5 минут, сервер сообщает о потере связи.

## Как обновить

Перед обновлением рабочего сервера согласуй перезапуск и убедись,
что автоматическая реальная торговля **выключена**. Уже размещённые
брокерские заявки обновление не отменяет. В рабочем окружении не выполняй
команды без согласования.

```bash
cd /opt/t-invest-bot
git branch --show-current
git status --short
sudo bash scripts/update_server.sh
sudo bash scripts/enable_extension_route.sh invest.argokov.ru
```

Второй скрипт обновляет ровно виртуальный хост T-Invest Bot для отчётов
расширения размером до 2 МБ, сохраняет резервную копию и проверяет
`nginx -t` перед применением.

## Подключение клиента

1. Открой Яндекс Браузер и войди в свой кабинет `https://invest.argokov.ru/`.
2. Выбери отслеживаемого автора в настройках кабинета.
3. Открой **Обзор → Мониторинг** и нажми **Скачать расширение (.zip)**.
4. Распакуй ZIP на компьютере в постоянную папку.
5. Открой `browser://extensions` → **Режим разработчика** →
   **Загрузить распакованное**; укажи папку `t-invest-pulse-extension`.
   Если расширение установлено раньше, обнови его через кнопку
   «Обновить» на странице расширений после замены файлов в папке.
6. В расширении укажи адрес панели и **ключ своего кабинета**. Логин
   `admin` не нужен и не вводится: сервер сам определяет кабинет по ключу.
   Ник автора Пульса выбирается отдельно в панели и не является логином клиента.
7. Нажми **Проверить связь** и убедись, что расширение показало правильный
   клиентский кабинет и автора. Включи передачу сделок и сохрани настройки.
   Затем нажми **Открыть сделки автора** — это только открытие страницы
   чужого публичного профиля, **не вход в банковский аккаунт автора**.
   Если сам Т-Банк требует авторизацию для API, можно войти только под
   **своим** банковским аккаунтом; расширение не выполняет вход и не сбрасывает
   банковскую сессию. Оставь страницу Сделки открытой.
   Для портфеля нажми «Портфель автора» и открой вкладку «Компании».
8. После первого списка админка показывает число инструментов и прогресс
   восстановления истории «Проверено N из M». Сделки за 24 часа появляются
   постепенно; закрывать вкладку Яндекс Браузера нельзя до завершения загрузки.
   Новые сделки отслеживаются параллельно с загрузкой истории.
   Старые ошибки Playwright остаются лишь в архиве журнала.

## Технические ограничения

- Интервал 3–5 секунд — желаемая частота, а не гарантия. Большой список
  инструментов и фоновая вкладка увеличивают интервал и время первого снимка.
- Расширение опирается на внутренние API веб-версии банка. Изменение схемы
  ответов может потребовать обновления расширения.
- После входа отдельно загружаются история за 24 часа и история за 30 дней.
  Поскольку автор может иметь сотни инструментов, расширение загружает данные
  **постранично** и сохраняет прогресс в своём кабинете. Новые сделки
  продолжают проверяться независимо.
- Для 30 дней сервер принимает страницы до 200 операций каждая; общая
  безопасная граница хранения — 20 000 исторических операций на автора.
  Если этот предел достигнут, прогресс остановится с ошибкой, а данные не
  будут ошибочно отмечены как полные.
- Уже сохранённая история за 24 часа остаётся доступной и не теряется.
  Данные за месяц доступны через кнопку **«Посмотреть за месяц»** в обзоре.
  До окончания загрузки отображаются частичные результаты и прогресс.
- **Демо-копирование новых сделок** подключено к прежним лимитам и правилам
  подтверждения. Оно включается отдельно в панели. Старые операции из истории
  не копируются.
- **Реальные брокерские заявки** используют прежний модуль T-Invest API.
  Если клиент подключил торговый токен, выбрал счёт и сохранил режим
  «Подтверждение» или «Авто», новые сигналы расширения проходят существующие
  лимиты и правила. Отдельных разрешений для расширения нет.
  Подтверждённые старые сделки из истории никогда не отправляются брокеру.
  Сигналы записываются в устойчивую очередь с идентификатором: неоднозначный
  результат после сбоя требует ручной сверки, а не повторной отправки.
  **Работа на живом брокерском счёте после этой интеграции не проверена.**
- **Портфель автора** читается расширением только из видимого раздела
  «Портфель → Компании» выбранного пользователя. В меню расширения есть
  кнопка «Портфель автора»: открой профиль, затем эти вкладки.
  Существующий серверный парсер распознаёт доли и сопоставляет с
  подтверждённым списком инструментов; скрытые позиции считаются
  неизвестными, а не нулевыми.
- Из банковского браузера не отправляются cookie, пароли, банковские
  токены, sessionId или служебные заголовки запросов. URL с sessionId
  используются только внутри браузера для повторения того же запроса.
- Расширение — источник данных. Решение о демо- или реальной заявке
  принимает прежняя торговая логика на сервере в соответствии с настройками
  конкретного клиента. Токены банка остаются в его браузере, торговый
  API-токен — в защищённых данных его кабинета. История за 24 часа и 30 дней
  используется только для отображения, не для автоматического копирования.

## Диагностика v0.7.3

Открой значок расширения → **Диагностика подключения** → **Обновить диагностику**.
Панель показывает версию, каждую открытую вкладку профиля, доступ к сайту,
ответ скрипта вкладки, автора, наличие API и подтверждения UUID, этап,
время проверки, HTTP или известную браузеру сетевую ошибку и следующий шаг.
В диагностике нет ключа кабинета, заголовков банка или query-параметров API.

- **Нет вкладки / wrong_page / wrong_author:** нажми «Открыть сделки автора».
- **Нет ответа скрипта:** после установки или обновления расширения открой
  новую вкладку этой кнопкой; проверь разрешение доступа расширения к сайту.
  Бесконечно нажимать F5 не требуется.
- **dashboard_401 / dashboard_403 / dashboard_pairing:** сохрани ключ из
  своего кабинета клиента. Это не потеря входа в банк. Расширение не требует admin.
- **pulse_401:** банк потребовал собственную сессию клиента; аккаунт автора не нужен.
- **pulse_403 / pulse_404:** доступ к данным ограничен либо маршрут API изменился.
  Проверь, видны ли сделки в самом банке; передай код диагностики разработчику.
- **pulse_429:** банк ограничил частоту, расширение повторяет запросы с паузой.
- **pulse_network / pulse_timeout:** сеть, блокировка браузером, TLS или тайм-аут.
  Один Failed to fetch не позволяет определить конкретную причину. Если
  webRequest получил ERR_CERT_*, панель показывает именно эту ошибку.
  Проверяй сертификаты по [инструкции банка](https://status.tbank-online.com/certificates/),
  не отключай проверку TLS. Сетевой код перехвата хранится до навигации/закрытия
  вкладки или перезапуска фонового процесса и не заменяет текущий результат API.
- **api_format / author_format / api_address:** ответ или адрес не соответствует
  проверяемому контракту; снимок счётчиков не подтверждается.

### Получение API и доверенные домены

Без перехвата расширение запрашивает `/mybank/api/social-api-gateway/social/v1/profile/nickname/<nickname>`
на **том же origin**, проверяет `payload.id`, затем строит `/profile/<id>/instrument`.
Идентификатор из перехваченного URL обязательно сверяется с ответом профиля.
Если перехват пропущен, расширение также проверяет имена уже загруженных API
в Resource Timing вкладки. Используются только проверенные маршруты того же
origin; другие API hosts показываются в диагностике без query, но не вызываются.
Перехват остаётся дополнительным источником API query и трёх безопасных
заголовков (`x-app-name`, `x-app-version`, `x-platform`). Если nickname-запрос
пропущен, наблюдённый query инструментов используется локально для проверки
автора. Cookie, sessionId и банковские токены не читаются из хранилищ и не
отправляются в кабинет. Запросы не следуют непроверенным редиректам. Ответ `opaqueredirect` проверяется
по правилам 0.7.2 ниже; если адрес недоступен, показывается `pulse_redirect`,
если он небезопасен — `pulse_redirect_blocked`. webRequest показывает HTTP, целевой hostname (без пути/query)
и время сетевого события. `ERR_ABORTED` сам по себе не доказывает ни редирект,
ни проблему TLS; сетевое событие может относиться к другому запросу вкладки.
Регистр nickname сохраняется в запросах, сравнение авторов нечувствительно к регистру.

Manifest `content_scripts.matches`, `host_permissions`, фильтры webRequest и
проверки адресов ограничены `tbank.ru`, `www.tbank.ru`, `tbank-online.com`,
`www.tbank-online.com`. Зеркало подтверждено [страницей банка](https://status.tbank-online.com/)
через её ссылку «Перейти». Другие `.com`, поддомены и API hosts не добавляются
по сходству имени. Запрос на другой origin не повторяется расширением.
В MV3 для перехвата нужны разрешения и на URL запроса, и на инициатора:
[документация Chrome](https://developer.chrome.com/docs/extensions/reference/api/webRequest).

Смена страницы, автора или ключа сбрасывает проверку UUID и состояние истории;
перед отправкой проверяются страница, ключ, включение мониторинга и автор кабинета.
Кэш перехвата живёт в `storage.session`, переживает сон service worker, очищается
при навигации и закрытии вкладки. Сбойный URL не переиспользуется бесконечно.
Скрипт запускается на `/invest/*`, поэтому переход внутри приложения из раздела
инвестиций на профиль обнаруживается очередным циклом. При переходе из другого
раздела банка внутри SPA открой профиль новой вкладкой через кнопку расширения.

Fallback использует существующий недокументированный контракт банка: если банк
требует дополнительные параметры, а его собственные запросы тоже не наблюдаются,
панель покажет HTTP/формат/сетевую ошибку, а не обещание, что F5 всё исправит.
Проверки выполняются офлайн. Доступ к API в реальном браузере клиента, включая
его сертификаты и ограничения банка, требуется подтвердить при установке.
Ни production, ни торговые настройки этот выпуск автоматически не обновляет.

### Исправление 0.7.2: HTTP 301

Переадресация API на том же HTTPS origin допускается только при сохранении
всего суффикса `/social/v1/profile/<автор или UUID>/...` (кроме конечного `/`).
Location берётся из webRequest только для точного URL и вкладки, не старше 15 секунд.
Не более четырёх запросов, с обнаружением циклов. Другой домен, автор, вход
или произвольная страница не вызываются. Уже загруженные запросы вкладки
принимаются с тем же ограничением origin и контрактом пути, без требования
устаревшего префикса `/mybank/api/invest/`. URL и параметры остаются локально.

### Исправление 0.7.3: маршрут автора и согласованная диагностика

Fallback использует подтверждённый в `docs/PULSE_RESEARCH.md` и `pulse_live.py`
префикс `social-api-gateway`, а при пропущенном nickname-запросе берёт префикс
и query уже наблюдённого списка инструментов. Пустые app-заголовки повторного
запроса не стирают сохранённые безопасные заголовки страницы.

Во время нового цикла код — `checking`, без HTTP/текста предыдущей ошибки.
Последний завершённый сбой показывается отдельно вместе с его этапом, временем
и точным путём запроса без query. Поэтому прошлый HTTP 404 автора не может
отображаться как текущий отказ списка инструментов. Сетевой HTTP webRequest —
отдельное событие вкладки, а не подтверждение текущей проверки расширения.
