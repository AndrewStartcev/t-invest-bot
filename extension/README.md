# Расширение Пульса для Brave / Chrome (MVP, только чтение)

**Статус:** экспериментальный источник, не допущен к реальной торговле. Текущий
Playwright-монитор продолжает существовать отдельно. Банковский логин, пароль,
SMS, cookies и токены T-Invest API расширение **не** отправляет серверу.

## Проверка на сервере — без веток и ручной сборки архива

Обновляй только ветку `main`. После первого успешного релиза на VPS
админка сама формирует ZIP из файлов `extension/`. Ключ доступа в ZIP
**не** помещается.

Перед обновлением убедись, что **нет активных заявок**, а реальная торговля
в админке **выключена**: штатный скрипт останавливает приложение и затем
перезапускает его. Уже выставленные лимитные заявки он не отменяет.
Проверь, что `/opt/t-invest-bot` находится на `main`, а локальных
изменений нет. Затем, после согласования обновления рабочего сервиса:

```bash
cd /opt/t-invest-bot
git status --short
git branch --show-current
sudo bash scripts/update_server.sh
sudo bash scripts/enable_extension_route.sh invest.argokov.ru
```

**Важно:** первый скрипт обновляет код и перезапускает сервис, а второй
проверяет и обновляет только виртуальный хост Nginx, сохраняя копию
старого конфига. Не выполняй команды при несогласованных изменениях
или во время активной торговли. Другие сайты Nginx не меняются.

Проверка:

1. Войди в `https://invest.argokov.ru/` под своим логином.
2. Открой **Обзор → Мониторинг → Скачать расширение (.zip)**.
3. Распакуй ZIP в отдельную постоянную папку на компьютере.
4. Открой `brave://extensions/`, включи «Режим разработчика» и
   «Загрузить распакованное», выбери папку `t-invest-pulse-extension`.
   **Веб-страница не может установить распакованное расширение
   без подтверждения пользователя.**
5. В админке нажми «Скопировать ключ», вставь его в расширение вместе
   с URL `https://invest.argokov.ru`, логином кабинета и ссылкой автора.
6. Нажми «Проверить связь» в расширении, открой «Сделки» в авторизованном
   Т-Банке и обнови F5. В админке дождись
   **Расширение подключено (чтение)**.
7. Проверь журнал, Telegram и отсутствие реальных заявок из расширения.
   Серверного входа в Т-Банк для этого канала не требуется.

**Это экспериментальный read-only монитор**: пока нельзя обещать 99%
полноты или 3–5 секунд в фоне браузера. Текущие серверные процессы
сами по себе не умеют читать банковскую сессию с компьютера клиента,
поэтому его браузер с расширением должен оставаться включённым.

## Быстрая проверка без изменения production

1. Проверь ветку `feature/pulse-browser-extension-mvp` на **отдельной тестовой
   копии** проекта. Установи зависимости `python -m pip install -r requirements.txt`
   и запусти `python demo_admin.py`. Адрес локальной панели:
   `http://127.0.0.1:8765/`.
2. Укажи в настройках **точную** ссылку на нужного автора Пульса.
   Режим «Реальная торговля» оставь **Выключена**. Настрой Telegram
   (токен бота и числовой chat_id) и проверь отправку штатной кнопкой.
3. В панели открой **Обзор → Мониторинг → Скопировать ключ расширения**.
   Ключ уникален для кабинета и сохраняется только на этом сервере.
   Не публикуй его и не вставляй в переписку/логи.
4. В Brave открой `brave://extensions/`, включи **Режим разработчика**,
   выбери **Загрузить распакованное** и каталог `extension/` из этой ветки.
5. Открой значок расширения. Для локальной проверки введи
   `http://127.0.0.1:8765`; для разрешённого HTTPS-развёртывания —
   `https://invest.argokov.ru`. Укажи логин кабинета (`admin` в
   локальной установке), ту же ссылку на автора и скопированный ключ.
   Выбери 5 секунд, включи мониторинг, **Сохранить**, затем
   **Проверить связь**. Должно появиться «Ключ принят сервером».
6. Нажми **Открыть сделки**. Авторизуйся на сайте Т-Банка **в этом же
   браузере** привычным способом. Перейди в раздел **Сделки** автора и
   сделай **F5**, чтобы расширение увидело внутренний запрос банка.
   Оставь вкладку открытой; для измерения 3–5 секунд — на переднем плане.
7. В админке открой **Обзор → Мониторинг**. Ожидаемый статус:
   **Подключено (чтение)**, дата «Отчёт расширения» обновляется.
   Первый снимок создаёт исходную точку; исторические сделки не
   создают новых сигналов.
8. Когда автор **публикует новую** операцию, счётчик «Сделок расширения»
   увеличивается, в «Журнале» появляется запись с источником
   `extension_trade`. Уведомление о сделке идёт в Telegram, если
   в кабинете включён мониторинг и не приостановлены уведомления.
   **Реальная заявка не отправляется.**
9. Для проверки аварии **закрой банковскую вкладку**. При работающей
   тестовой админке примерно через 30 секунд без отчётов появится
   `offline`, запись в журнале и Telegram-сообщение (если задан
   chat_id). Открой вкладку снова, F5: при восстановлении будет
   сообщение. Для проверки именно закрытого профиля нужен профиль
   владельца, который явно переключит видимость; **не меняй чужие
   данные и не экспериментируй с чужим счётом**.
10. Через 90 секунд проверь, что профиль повторно запрашивается,
    а быстрые проверки продолжаются отдельно. В DevTools вкладки
    `Network → Fetch/XHR` можно наблюдать запросы `instrument`.
    **Не сохраняй HAR с cookies и заголовками авторизации.**

## Что означает статус

- `ok` — полный снимок счётчиков подтверждён сервером.
- `restricted` — HTTP 403/404: профиль или сделки недоступны.
  Это **не абсолютное доказательство**, что автор сделал профиль закрытым.
- `login_required` — нужна повторная банковская авторизация.
- `unavailable` — сетевой сбой, изменение внутреннего API или неполные данные.
- `rate_limited` — банк ограничил запросы: расширение замедляет опрос.
- `background_throttled` — вкладка в фоне, короткий интервал не выдерживается.
- `offline` — сервер больше 30 секунд не получает отчёты.
- `stopped` — пользователь выключил расширение.

Если видишь «Не найден запрос списка инструментов», открой вкладку
«Сделки» **после** установки расширения и нажми F5. Если получаешь
HTTP 401/403 — сначала проверь банковский вход. При HTTP 422
сравни выбранные URL профиля в двух местах и проверь консоль.

## Многопользовательская установка и HTTPS

Ключ расширения выдаёт **конкретный кабинет** через
`GET /api/extension/pairing` (только после обычного входа в админку).
Отчёты поступают в `POST /api/extension/report` с заголовками
`X-TInvest-Extension-Client` и `X-TInvest-Extension-Key`.
Это единственный внешний маршрут без Basic Auth, но он требует
случайного клиентского ключа и не принимает торговые команды.
Прямое обращение к внутреннему worker без его backend-ключа запрещено.

После **отдельного согласования релиза** нужно применить новый nginx
vhost из `scripts/render_nginx.py`, проверить `nginx -t`, конфигурацию
шлюза и права на ключи, затем аккуратно перезапустить тестовую службу.
Простого обновления файлов Python недостаточно: старый nginx вернёт 401
на расширение. Не заменяй nginx-конфигурацию production вслепую.

## Частота и метрика 99%

5 или 3 секунды — **целевой интервал запуска**, а не гарантия
появления сделки за это время. Банк сам может публиковать операции с
задержкой. Chrome/Brave замедляют фоновую вкладку; при закрытом
браузере расширение вообще не работает. Банк может изменять закрытое API
или вводить ограничения частоты.

Метрику зафиксировать отдельно: количество **публично доступных
опубликованных операций**, найденных расширением / количество всех
опубликованных операций в контрольном интервале; также считать
дубликаты, ложные сигналы и задержку между публикацией и обнаружением.
Без независимой контрольной истории **99% не подтверждены**. В этом
MVP хранится счётчик полученных событий, но нет доказанной внешней
проверки полноты. Реальный торговый режим намеренно не связан с
этим каналом.
